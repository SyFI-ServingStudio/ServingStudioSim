Three files are copied byte-for-byte: `topk.cu`, `persistent_topk.cuh`, and
`torch_utils.h`. Their upstream paths and SHA-256 digests are recorded in
`source_manifest.json` and verified before every build or load, so drift from

files stay byte-identical to their Apache-2.0 originals.

`profiling/runners/attention/dsa_persistent_topk_native/NOTICE.md`.

## Launch-only bindings over third-party kernels

These files are **project-owned** and covered by this project's licenses, but
they are worth listing because the code they call is not:

| File | Calls into |
| --- | --- |
| `profiling/runners/gemm/csrc/flashinfer_trtllm_blockscale_grouped_gemm.cu` | FlashInfer's vendored TensorRT-LLM FP8 block-scale grouped GEMM |
| `profiling/runners/moe/csrc/moe_finalize_routing.cu` | FlashInfer's vendored TensorRT-LLM MoE finalize kernels |
| `profiling/runners/elementwise/csrc/fp8_block_quant_grouped.cu` | TensorRT-LLM's grouped BF16→FP8 quantizer, via the FlashInfer-vendored header |

Each binding reproduces only the launch policy; the kernel bodies stay in the
upstream headers and are obtained through the dependency, not copied here.

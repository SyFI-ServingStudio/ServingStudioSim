# L5 — Worker

A **worker** models one serving worker (one GPU group's worth of execution). It owns
the request lifecycle: admit queued requests under a KV-memory budget, form a batch,
ask the L4 model how long the batch's iteration costs, advance the clock, then
book-keep tokens and KV until requests finish. It is the **first layer that holds
mutable simulation state**; everything below it (L4 → L1) is a pure cost query.

## Role and boundary

- **Sees:** one arch (as `Arc<M>`), one KV pool, its own request queue and clock.
- **Doesn't see:** other workers, or how requests reach it — that is the
  orchestrator's concern.

## The L6-facing surface

The L6 pool drives a worker through three methods; events are pushed into a
caller-owned sink so the worker keeps no drainable outbox:

| Method | Role |
|---|---|
| `enqueue(WorkerMsg::Request(rid))` | hand the worker an admitted request. |
| `tick(now, events) -> Option<Time>` | advance the FSM as far as it can at `now`, push self-tagged events, return the next wakeup (`None` = quiescent). |
| `status() -> WorkerStatus` | queued + active counts for the pool's load view. |

The request slab is the shared `RequestStore` (`SharedRequests`), injected at
construction and borrowed transiently inside each method.
`release_request(rid, current_kv)` is the external cancellation entry point.

## The tick FSM

State is `WorkerFsmState {Idle, Active}` crossed with the batch cursor
`BatchFsmState`. `tick` is a state-forwarding loop over three stages:

1. **`form_batch`** (Idle) — admit one fresh prefill from the queue if
   `KvAdmission::try_admit` passes the KV-memory check, then drain ready promises
   into the iteration's `prefill_admits`. Stays Idle when nothing is admitted and no
   decode is in flight.
2. **`start_iter`** (Active / NotStarted) — build the `UnifiedArchInput`, run one
   CostTree eval pass on the L4 model, and arm `compute_end = now + cost_time`
   (`agg.m.time_ms` is the clock). The worker waits until `now >= compute_end`, then
   the cursor goes Computing → Done.
3. **`complete_iter`** (Active / Done) — advance decode tokens, transition admitted
   prefills to decoding, release finished requests' KV, and emit
   `RequestComplete { worker, req }` into the event sink. Back to Idle.

## Admission and batching primitives

- **`KvPool`** — the KV-cache memory budget. The worker sizes its own pool at
  construction as `attn_kv_bytes / model.kv_bytes_per_token` (L5 owns the division;
  the arch owns the per-token footprint). `projected_peak` estimates peak KV until
  all live decodes drain, evaluating only at decode-exit steps — a heuristic
  admission guard, not an exact bound.
- **`Batch`** — the in-flight request group: this iter's `prefill_admits` plus the
  decoding set, with projected-peak-KV accounting.
- **`KvAdmission` (`Strict`)** — the go/no-go that keeps a batch within its projected
  peak KV.

## cost_log (optional, per-iteration)

When a `log_dir` is supplied, the worker opens a `CostLogger` against the model's
`cost_log_manifest()`. `start_iter` always fills the reused `cost_slots` buffer;
when logging is active it also captures per-leaf typed inputs and writes one
`CostLogEntry` per iteration (per-slot time / coverage, the group input section, the
aggregate time / energy). A failed open disables logging with a warning — it never
aborts the sim.

## Directory and current set

Iter-wise workers include `BareboneWorker` (single-group unified),
`HpUnifiedWorker` (one batch per attention-DP shard), and the PD pair
`PdPrefillWorker` / `PdDecodeWorker`. `WorkerConfig` is their construction tier (KV
budget plus hot-path logging controls). Worker selectors are serde tagged enums
(`IterWorkerSel`), the symmetric sibling of the arch selector, co-located with the
workers they pick.

## Up / down

- **Below (required):** the L4 model via `IterwiseUnifiedModel` (`eval_iter`,
  `kv_bytes_per_token`, `cost_log_manifest`), held as `Arc<M>`.
- **Above (consumer):** the L6 orchestrator pool enqueues requests, ticks due
  workers, and receives self-tagged events through the shared sink.

## Layer invariants

- L5 is the first stateful layer; L4 and below stay pure cost queries.
- The worker sizes its own KV pool from the arch's per-token footprint.
- The clock advances by the arch's returned iteration time (`agg.m.time_ms`).
- Events are pushed into a caller-owned sink, not returned or buffered on the worker.

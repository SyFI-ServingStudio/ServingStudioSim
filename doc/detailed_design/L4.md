# L4 — Model arch

A **model_arch** is the full-model wire file for one worker type. It picks an L3
worklet set, forwards the numeric `ModelCfg` + `ParallelCfg` into each worklet's
config, assembles the embedding → layers → lm_head structure, and **compiles the
per-iteration CostTree once**. It owns the parallelism layout and is the worker's
(L5) sole view of "the model".

## Role and boundary

- **Sees:** worklets, the model config, the parallel config.
- **Doesn't see:** simulation state — the KV pool, admission, or the clock are the
  worker's. The worker, in turn, never sees worklets or kernels.

## The L4 ↔ L5 contract

A worker hands the arch a per-iteration input and gets back one aggregated cost. The
contract is the `IterwiseUnifiedModel` face:

| Method | Role |
|---|---|
| `eval_iter(batch, &mut slots, &mut scratch) -> LeafMetrics` | per-iter CostTree eval: fill `slots` with per-leaf metrics, aggregate through the caller-owned scratch, return the root (`.m.time_ms` is the clock). |
| `eval_iter_with_inputs(...)` | same, plus capture each leaf's typed `SlotInput` for cost_log (the clone is paid only here). |
| `cost_log_manifest() -> CostManifest` | the slots + flat nodes so a consumer reproduces `total_time_ms` from a row. |
| `kv_bytes_per_token() -> u64` | KV footprint per token; the worker divides its memory budget by this to size its `KvPool`. TP archs report the per-rank (head-sharded) footprint; the dense arch reports the full model's. |
| `gpus_per_replica() -> u16` | GPUs one replica spans; L5/L6 only read it. |

The per-iteration input is `UnifiedArchInput` — `groups: Vec<ArchGroupInput>` (dense
local has exactly one) plus `tokens_per_source_rank` (the FFN routing view, empty
for dense). An `ArchGroupInput` is the batch state: `batch_tokens`, the
`prefill_tokens` / `decode_tokens` split, the `(prefix_len, append_len)`
`prefill_chunk_pairs`, `decode_kv_lens`, `total_kv_len`.

## The build shape

Every arch follows `build_configs → resolve_configs → build`:
`build_configs(&ModelCfg, &ParallelCfg)` produces the raw worklet/op configs
(`gpu_name` baked); `resolve_configs` yields the per-rank shapes with sub-configs
baked; `build(name, resolved, bridge)` instantiates each worklet/op (profiling its
kernels through the bridge), then **compiles the CostTree once** and caches its
flattened form + slot count on the model. The per-iter `eval_iter` therefore only
evals leaves and aggregates through caller-owned buffers — no per-tick recompile,
`String` minting, or scratch allocation. A dry-run bridge turns `build` into a
coverage tally with no separate traversal.

The compiled structure folds the homogeneous layer:
a `Labeled` root wraps a `Sum` of embed, a `Scale{num_layers}` over one layer's
`Sum(pre_attn, attn, post_attn)`, final_norm, and lm_head. The `Scale` fold is the
economy — one worklet instance per type is built and its leaves minted once; the
fold supplies the `×num_layers` at aggregate, so the layers are never materialised N
times. `eval` streams the leaves in the exact order `compile` minted slots.

## Configs and selectors

- **`ModelCfg`** — the resolved numeric transformer dims (hidden, heads, layers,
  dtype, …), parallelism-agnostic; `from_json` loads a HuggingFace `config.json`,
  the only runtime source of dims.
- **`ParallelCfg`** — the resolved `tp_size` / `ep_size` / `num_hp_groups` degrees +
  `gpu_name`, the single source of truth threaded into every kernel lookup. Dense
  local is all degrees 1 (`ParallelCfg::local`).
- **`IterArchSel`** — the serde tagged arch selector, provider-first (selecting the
  tag is the only way its params appear). `tp_size` is absent only from
  `Llama3Dense`; `Llama3DenseTp` carries `tp_size`; `Llama3DpAttnTpFfn` carries
  `attn_tp_size` / `ffn_tp_size`. `ModelSpec` is flattened into every tag, with
  `model_config` + `fp8` as cache-key params.

## Directory and current set

- **Live archs:** `llama3_dense` (Local, single GPU), `llama3_dense_tp`
  (tensor-parallel, each block ends in a `tp_allreduce`), and `llama3_dp_attn_tp_ffn`
  (attention-DP + FFN-TP, paired with `hp_unified` or PD decode).
- **Below (assembled):** L3 worklets + L2 atomic ops, and through the CostTree, L1
  kernels.
- **Above (consumer):** the deployment layer runs the build cascade and selects the
  arch by tag; the L5 worker holds the model as `Arc<M>` and calls `eval_iter`.

## Layer invariants

- The arch compiles the CostTree once; the per-iter path only evals + aggregates.
- `Scale{num_layers}` folds only the provably-identical homogeneous layer.
- The arch owns the parallel layout; `gpu_name` in `ParallelCfg` is the single
  source threaded into every kernel lookup.
- The arch reports the per-token KV footprint; L5 owns the division that sizes the
  pool.

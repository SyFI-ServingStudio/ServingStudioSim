# L1 — Kernel / Profiling

L1 answers one question: **how long does one kernel take on one GPU?** It is the
only layer that produces a number; every layer above it composes L1's outputs and
invents nothing. L1 is split across two languages that meet at a PyO3 bridge — the
Python **profiling** package that measures and caches, and the Rust **timing**
crate that fits and serves those measurements and hosts the CostTree.

## Role and boundary

- **Sees:** a kernel config (identity + `gpu_name` + backends) plus a per-call
  shape, and the profiled samples in `profile.db`.
- **Doesn't see:** ops, models, parallelism, or the simulation. L1 has no notion of
  a request, a batch of requests, or a clock — only a kernel shape and its metrics.

## Half A — Profiling (Python, `profiling/`)

The source of truth for measured timings. The simulator never measures a kernel
itself; it asks this package, which either returns a cached measurement or (when
JIT profiling is enabled) launches the real kernel on a real GPU to produce one.

The package is split strictly by responsibility:

- **L1a — measurement (`runners/`, `profilers/`).** Given concrete kernel
  arguments, allocate tensors, launch the kernel, time it (CUPTI / energy
  primitives), and return a `Metrics` dataclass. Knows nothing about SQLite,
  caching, or who asked — a runner can be developed and tested without a database.
- **L1b — cache + serving (`db/`, `facade.py`, `perf_api.py`, `exec/`).** Owns the
  SQLite cache, the `(kernel, backend)` registry, the public query API, the
  JIT-profiling policy, and the subprocess execution that drives the L1a runners.

The entire public surface is the `profiling.perf_api` facade. Its key symbols:
`get_<kind>_times` (batch query → cached `Metrics` or `MissingEntry`),
`count_missing_<kind>` (read-only dry run, never profiles), `enable_jit_profiling` /
`disable_jit_profiling` (process-wide: may a miss trigger a real run?), and
`get_current_gpu_name`. The `get_<kind>_times` / `count_missing_<kind>` names are
**generated** from the registry — one pair per kernel kind; callers never
hand-write wrappers.

Two internal paths, both funnelled through `perf_api`:

- **Read path** (`facade._get_times`): resolve `gpu_name` → query the kind's table
  → hits return `Metrics`, misses return `MissingEntry`; if there are misses and
  JIT is enabled, `run_profile_batch` fills them and re-queries.
- **Profile path** (`db/batch.py`, the single runner funnel): coerce specs to typed
  `KernelArgs`, group by `(backend, gpu_count)`, reserve GPUs, and spawn
  `python -m profiling.exec.local_worker` in the spec's env. The main/simulator
  process therefore **never imports torch or a runner** — the heavy import happens
  only in the worker subprocess after a GPU is reserved.

The registry spine is the `KernelProfilerSpec`: one row binding a
`(kernel_kind, backend)` pair to its args schema, lazy runner ref, SQLite table
name, metric family (compute vs comm), outlier policy, and subprocess env. The DB is
one table per args schema, keyed `UNIQUE(gpu_name, backend, <args...>)`; metric
columns are chosen by `metric_family` (compute → `time_ms, tflops,
memory_bandwidth_gbps, energy_j`; comm → `time_ms, algbw_gbps, busbw_gbps,
energy_j`, with `message_size_bytes` a cache-key column, not a measured result).

## Half B — Timing (Rust, `simulator/src/timing/`)

Turns kernel shapes into metrics and composes leaf metrics into a per-iteration
total. It never measures a GPU; it asks the Python profiling layer for samples,
fits an interpolating cache over them once, then evaluates that cache millions of
times. It also owns the **CostTree**, the compile-once / evaluate-per-iteration
structure every layer above uses.

The upward surface (re-exported from `crate::timing`): the `KernelConfig` trait and
the `Probe` / `CacheProbe` per-leaf cost queries; the cost-tree types (`CostTree`,
`CostNode`, `CostTreeBuilder`, `Evaluator`, `FlatCostNode`, `CostManifest`); the
metric / coverage types (`LeafMetrics`, `Metrics4`, `CoverageFlags`); the cost_log
capture types (`SlotInput`); the sweep grid (`SweepGrid`, `Axis`, the `SweepCoords`
derive); and the PyO3 bridge (`PerfApiBridge`).

Directory landmarks:

| Path | Holds |
|---|---|
| `bridge/` | The PyO3 boundary to `profiling.perf_api`: `get_times` / `count_missing` / JIT toggle / `get_current_gpu_name`, plus the wire types (`KernelKind`, `ArgsPayload`, `KernelMetrics`). |
| `kernels/` | One file per kernel kind + the generic engine. `engine.rs` holds `KernelSpec` / `KernelConfig` and `Kernel<S>`; each kind file declares its `Config` / `Input` / `KIND` / `sweep_grid` / `enumerate` and calls `register_kernel!` (no central enum). |
| `cache/` | Fit profiled samples into an interpolating cache and evaluate off-grid; `Metrics4`, `LeafMetrics`, `CoverageFlags`, and the branchless `locate` (the measured hot-path floor). |
| `cost_tree.rs` | `CostNode` / `FlatCostNode` / `CostTree` / `CostManifest` + `Evaluator` + `aggregate`. |
| `sweep.rs` | `SweepGrid` + `Axis` presets (the profiler↔sim contract curves) + `SweepCoords`. |
| `slot_input.rs` | `SlotInput`: the closed enum of leaf inputs captured for cost_log. |

The two phases are the central idea. **Build** (once per run) enumerates each
kernel's sweep grid, fetches the profiled samples through the bridge, fits a cache
per backend, and compiles a `CostTree` that flattens to a `Vec<FlatCostNode>` plus a
`CostManifest` sidecar. **Eval** (every iteration, the hot path) interpolates each
leaf's cache for the current shape, streams the metrics into the slot buffer in
visit order, and folds them to one `LeafMetrics` in a single reverse pass over
reused scratch. Names exist only at build time — never on the hot path or in log
rows.

Build-time vs runtime safety: `PerfApiBridge::new()` calls `disable_jit_profiling`,
so the default is sim-runtime-safe — a cache miss raises `MissingEntry` rather than
launching a GPU profile mid-simulation. Only the `build-cache-only` entry point
re-enables JIT.

## Cross-language identity

The seam is carried by a string that must stay equal on both sides:
`KernelSpec::KIND` (Rust) equals the `profile.db` table name equals the Python
facade stem, and the bridge derives the call as `get_{kind}_times`. A kernel's
`ArgsPayload` field set is the wire schema the Python `*Args` dataclass validates
field-for-field. The Python registry validator enforces the triple equality.

## Layer invariants

- L1 is the only measured layer; every number originates here from `profile.db`.
- `gpu_name` is part of the kernel config, baked in, keyed per GPU — never ambient.
- Structure is compiled once; the hot path is pure interpolation plus a fold.
- Coverage flags (extrapolated / JIT / no-coverage) OR up the tree so an off-grid
  leaf is visible at the root.
- The main/simulator process never imports a GPU runtime; measurement happens only
  in a profiling worker subprocess.

# L2 — Op

An **op** is a named composition of one or more L1 kernels with `compile` / `eval`
entry points into the CostTree. L2 is the first layer that gives a cost leaf a
*semantic name* (`model.attn.o_proj`) and, for compound ops, the op-specific math
that turns one logical operation into several kernel calls.

## Role and boundary

- **Sees:** per-rank shapes; holds its L1 kernels as `Arc<K>` and forwards.
- **Doesn't see:** a `ParallelConfig`, simulation state, or which worklet called it.
  L2 is parallelism-agnostic and sim-state-agnostic — it sees already-partitioned
  shapes and returns metrics.

## Two forms of op

| Form | Where it lives | Example |
|---|---|---|
| **Atomic** — `Op<K>`, a generic single-kernel wrapper | no file; instantiated at the L4 wiring site with `Op::new(name, kernel)` | `qkv`, `o_proj`, `gate_up`, `down`, `lm_head`, `rms_norm` |
| **Compound** — a hand-written struct with multi-kernel, custom cost math | its own file under `op/<family>/` | `FlashInferAttentionOp` |

Adding an atomic op needs no code in this layer — it is one `Op::new` line at the
wiring point. A compound op earns a file only when its input does *not* map 1:1 to a
single kernel input.

## The compile / eval contract

Both forms expose the same pair, and they must mirror each other:

- **`compile(&mut CostTreeBuilder) -> CostNode`** mints this op's leaf slot(s). An
  atomic op is one `Leaf`; a compound op is a small `Sum` / `Max` of fixed leaves.
  The leaf carries the op's dotted name plus the kernel's kind / one-line config.
- **`eval(&Input, &mut Evaluator)`** pushes each leaf's `LeafMetrics` in the **same
  child order** that `compile` minted slots, so the evaluator cursor lines up with
  the slot index.

The leaf count is fixed at compile regardless of request count: a variable
per-request fan-out aggregates *into* a fixed slot rather than minting one slot per
request. Each leaf's typed input is captured into the `SlotInput` enum only when the
evaluator is recording; the `K::Input: Into<SlotInput>` bound is the central
registry — a kernel input not listed in `timing::slot_input::log_inputs!` fails to
compile here.

## The worked compound op

`FlashInferAttentionOp` dispatches one attention call over a sim batch to three L1
kernels (`kv_cache_append`, `flashinfer_attn_prefill`,
`flashinfer_attn_decode`) with three fixed leaves, minted regardless of request
count. The cache-append leaf writes every new token once per layer, with
`num_tokens = Σ prefill append_len + decode request count`; it is deliberately
separate from attention compute so measured vLLM cache writes align to their own
simulator slot. The `prefill` leaf **aggregates**: `eval` sums
the prefill kernel's cost over every `(prefix_len, append_len)` pair into that one
slot (a prefill/chunked request *is* the prefill kernel's cache cell, so it passes
through unconverted). The `decode` leaf **collapses** all decode requests to one
cell `(batch_size = count, total_tokens = Σ kv)`. This v1 cost model is exact when a
step has ≤1 prefill request — the common continuous-batching case — and
over-estimates only when several small-q prefills are batched.

## Directory and current set

- **Live:** `Op<K>` (atomic, no file) and `FlashInferAttentionOp` (compound,
  `op/attention/flashinfer.rs`).
- **Stubs:** `op/comm`, `op/moe`, `op/ssm` are one-line module headers holding the
  compound ops they will host.

## Up / down

- **Below (required):** L1 timing kernels via the `Probe` trait
  (`eval(&Input) -> LeafMetrics`, `kind`, `describe_config`).
- **Above (consumer):** L3 worklets, which call `compile` / `eval` on each op slot
  and never see an op's sub-kernels or internal normalisation.

## Layer invariants

- An op's internal composition is fixed and zero-overlap; cross-kernel overlap is a
  worklet concern, not an op concern.
- The leaf count is fixed at compile (INV-1); per-request fan-out aggregates into a
  fixed slot.
- `eval` pushes leaves in `compile`'s child order (INV-2).
- L2 is parallelism-agnostic and sim-state-agnostic.
- A leaf's backend is selected by a backend string in the config that passes through
  to L1; an op never swaps its kernel by type.
